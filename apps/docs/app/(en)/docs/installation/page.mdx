# Installation

Merid is published as a single package, `@meridui/react`. It contains the components, the stylesheet and the bundled Geist and Geist Mono variable fonts.

## Quick start with the CLI

In a Next.js, Vite or React Router project, one command does it all. It detects your package manager, installs the package, imports the stylesheet, removes the [template styles](#styles-from-your-project-template) that would override Merid and, if you want, adds the AI rules file and MCP config. Every change is shown as a diff before it is written.

```bash
npx @meridui/cli init
```

See [CLI](/docs/cli) and [Using Merid with AI](/docs/ai) for details, or follow the manual steps below.

## Requirements

- React 18 or 19 and the matching `react-dom`.
- A bundler that can import CSS from `node_modules`. Next.js, Vite, Remix, Parcel and webpack all can.
- Node.js 20 or newer for local development.

## Install the package

```bash
npm i @meridui/react
```

With other package managers:

```bash
pnpm add @meridui/react
yarn add @meridui/react
```

## Import the stylesheet once

Every component reads from one stylesheet. Import it once, as high in your tree as possible.

```tsx
import "@meridui/react/styles.css";
```

If you only want the design tokens — for example, to use the colours and spacing in your own components — import `@meridui/react/tokens.css` instead. It contains the custom properties and the font face, and no component rules.

`styles.css` includes a small base layer: `box-sizing: border-box`, the document font, colours, heading weight and focus ring, applied to `:root` at zero specificity (so any rule of yours wins). If your app brings its own document styles and you want none of it, import `@meridui/react/components.css` (tokens + components, no base) instead. Components set `box-sizing` on their own elements, so they render the same either way.

## Styles from your project template

`create-vite`, `create-next-app` and `create-react-router` give you a global stylesheet (`src/index.css`, `app/globals.css`, `app/app.css`). Its rules sit outside any cascade layer, so they beat Merid. The Vite template sets the page font and colours and, in older versions, styles every `button`. Next.js puts Arial on `body`, and without Tailwind it also adds `* { padding: 0; margin: 0 }`, which takes the padding off every component. That is the cascade doing what [Styling](/docs/styling) describes, but these are the template's defaults, not your styles.

`npx @meridui/cli init` finds these rules and offers to remove them. It prints the diff and asks first, or applies it with `--yes`. It only removes rules that still match what the generator wrote; a rule you have edited stays, and so does everything you added. `npx @meridui/cli doctor` lists any that are left.

To do it by hand, delete the template's rules for `:root`, `body`, headings, `a`, `button`, `code` and `#root`, and keep `body { margin: 0 }`.

We remove them instead of moving them into a layer below Merid. A layer would only stop them where Merid sets the same property. Rules Merid never sets, such as `text-align: center` on `#root` or `display: flex` on `body`, would keep laying out your app like the starter page.

### With Tailwind CSS

The default Next.js and React Router templates use Tailwind v4, whose reset (Preflight) lives in a cascade layer called `base`. Layers are ordered by first appearance, so when Merid's stylesheet loads first, Preflight lands above it and removes the padding, borders and background of buttons and inputs. Declare the order at the top of the Tailwind stylesheet and import that file before Merid's:

```css
/* app/globals.css */
@layer theme, base, merid, components, utilities;

@import "tailwindcss";
```

```tsx
// app/layout.tsx
import "./globals.css";
import "@meridui/react/styles.css";
```

`init` makes both changes. More in [Tailwind CSS](/docs/integrations/tailwind).

## Next.js (App Router)

Import the stylesheet in the root layout. The base typography and focus styles apply to the whole page; no class is needed.

```tsx
// app/layout.tsx
import "@meridui/react/styles.css";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  );
}
```

No `transpilePackages` entry is needed: the package ships compiled ES modules and CommonJS. Interactive components carry their own `"use client"` directive, so you can import them straight into server components.

## Vite

Import the stylesheet in your entry file, before your own CSS so that your rules follow Merid's in source order.

```tsx
// src/main.tsx
import "@meridui/react/styles.css";
import "./app.css";
import { createRoot } from "react-dom/client";
import { App } from "./App";

createRoot(document.getElementById("root")!).render(<App />);
```

## Font

Geist and Geist Mono variable fonts are bundled (`@meridui/react/fonts/Geist-Variable.woff2` and `GeistMono-Variable.woff2`) and loaded through `@font-face` from the package. Browsers only download a font when text uses it, so if you set your own family the file is never requested:

```css
:root {
  --mrd-font-sans: "Your Sans", system-ui, sans-serif;
}
```
